# 自動走行 ML 化 方針・要件定義

自動運転ラジコンカー（ライントレース）の ML パイプライン全体の方針と各モデルの要件を定義します。

---

## 全体アーキテクチャ

```
【Pi 側リアルタイムパイプライン】

カメラ取得 (30fps)
  ↓
[ステージ1] セグメンテーションモデル推論
  ↓ コース領域の二値マスク
ゾーンスキャン（既存ロジック流用: camera_receiver.py）
  ↓ top/mid/btm 座標・offset・detect フラグ
[ステージ2] モータ制御モデル推論（MLP・ONNX）
  ↓
モータ指令（PWM）
```

ステージ1でコース検出をMLに置き換え、ステージ2の制御モデルへの入力フォーマット
（`line_detect_*` / `line_offset_*`）は変えない。
これにより、ゾーンスキャン以降の既存コードはそのまま流用できる。

---

## ステージ1: コース検出モデル

### 設計思想

現在の `_build_line_mask()` による閾値二値化をMLモデルに置き換える。
ゾーンスキャン以降のロジックは既存コードを流用するため、
モデルの出力は「コース領域の二値マスク」のみでよい。

### モデル仕様

| 項目 | 内容 |
|------|------|
| タスク | 二値セグメンテーション（コース領域 vs 背景） |
| アーキテクチャ | 軽量 U-Net（Encoder 3〜4 Conv 層 + Decoder） |
| 入力 | 160×120 グレースケール 1ch（`float32`, 0〜1 正規化） |
| 出力 | 160×120 の 1ch マスク（sigmoid、0〜1）|
| 学習フレームワーク | PyTorch |
| エクスポート形式 | ONNX → NCNN 変換（INT8 量子化） |
| 推論エンジン | NCNN（Pi 上での ARM 最適化） |
| 目標推論時間 | **40ms 以内**（Pi 4 基準、検出レート 14fps 維持） |

### リアルタイム制約

C++ で書き直しても効果は薄い（推論の本体は NCNN の C++ カーネルが担うため）。
速度の鍵は以下の順に効く：

1. NCNN + INT8 量子化（2〜4× 高速化）
2. 入力解像度を小さく保つ（160×120 固定）
3. モデルを浅く・フィルタ数を少なく設計する
4. Pi 5 への移行（約 2× 高速化）

**実装前に必ず Pi 実機でベンチマークを取り、40ms 以内に収まるモデルサイズを確定してからフル学習に進むこと。**

### 学習スクリプト要件（train_seg.py）

1. **Dataset**
   - フレーム画像（PNG）とアノテーションマスク（PNG）のペアを読み込む
   - 入力: グレースケール変換 + 160×120 リサイズ + `float32` 正規化（÷255）
   - ラベル: 二値マスク（コース=1, 背景=0）を `float32` で読み込み

2. **モデル定義**
   - `nn.Module` を継承した軽量 U-Net
   - Encoder: Conv2d + BatchNorm + ReLU を 3〜4 段
   - Decoder: Upsample（bilinear）+ Conv2d
   - 最終層: Conv2d(1) + Sigmoid

3. **損失関数**
   - BCE Loss（Binary Cross Entropy）+ Dice Loss の組み合わせを推奨
   - コース領域のピクセルが少ない場合は pos_weight で重み付け

4. **ONNX エクスポート**
   - ダミー入力: `(1, 1, 120, 160)`（batch, ch, H, W）
   - opset_version=11
   - 出力後に NCNN の `onnx2ncnn` で変換・INT8 量子化する

## ステージ1: アノテーション

### 方針

走行ログ（保存フレーム）を下書きとして活用し、手作業を最小化する。

```
① 走行しながらフレームを保存（recorder.py 活用）
      ↓
② 現在のルールベース（_build_line_mask）で二値マスクを自動生成（下書き）
      ↓
③ LabelMe 等で誤検出・見落としを修正・確定
      ↓
④ 確定マスク（PNG）を学習データとして保存
```

### 目標データ量

| 場面 | 枚数目安 |
|------|----------|
| 直線（標準照明） | 200 枚 |
| カーブ進入・脱出 | 300 枚 |
| 照明変化（明るい/暗い） | 100 枚 |
| ノイズ多め（継ぎ目・影・誤検出場面） | 100 枚 |
| **合計** | **約 700 枚** |

全フレームを収集する必要はなく、**代表的な場面をサンプリング**すれば十分。

### アノテーションツール

- **LabelMe**（推奨）: ポリゴン選択・ブラシ塗り、ローカル動作、PNG マスク出力対応
- CVAT: Web UI、チーム向け
- 自作 GUI: 既存走行ログと連携しやすい場合に検討

## ステージ2: モータ制御モデル

### 設計思想（PID 制御の AI 化）

人間が手動でチューニングする「PID 制御」を深層学習によって自己学習・最適化させる。
AI に「過去の記憶」と「現在の状態」を同時に与えることで、
内部的に高度な非線形 PID コントローラーとして振る舞うように設計する。

- **P（比例）の学習**: 最新フレームの「中心からの距離（誤差 e）」から基本の操舵量を決定
- **I（積分）の学習**: 過去 10 フレーム分の距離を保持し、誤差の蓄積（∫e dt）を認識
- **D（微分）の学習**: フレーム間の距離変化量（de/dt）から急カーブへの先回り操作を獲得
- **動的ゲイン**: 現在のモーター値・設定スピードを入力し、状況に応じてゲインを可変

### モデル仕様

| 項目 | 内容 |
|------|------|
| タスク | 回帰（左右モーター出力の予測） |
| アーキテクチャ | MLP（多層パーセプトロン） |
| 入力サイズ | 90（9要素 × 10フレーム） |
| 出力サイズ | 2（左モーター・右モーター） |
| エクスポート形式 | ONNX（opset_version=11、入力 `(1, 90)`） |
| 推論エンジン | OpenCV DNN / ONNX Runtime |

### 入力データ仕様（90 ノード）

最新フレームから過去に向かって 10 フレーム分を 1 次元にフラット化して入力する。

【1 フレームあたり 9 要素（すべて正規化済み）】

| # | 要素 | 範囲 |
|---|------|------|
| 1 | 上領域（top）の線検知フラグ | 0.0 or 1.0 |
| 2 | 中領域（mid）の線検知フラグ | 0.0 or 1.0 |
| 3 | 下領域（btm）の線検知フラグ | 0.0 or 1.0 |
| 4 | 上領域の中心からの距離（offset） | -1.0 〜 1.0 |
| 5 | 中領域の中心からの距離（offset） | -1.0 〜 1.0 |
| 6 | 下領域の中心からの距離（offset） | -1.0 〜 1.0 |
| 7 | 現在の左モーター出力値 | -1.0 〜 1.0 |
| 8 | 現在の右モーター出力値 | -1.0 〜 1.0 |
| 9 | ベーススピード | 0.0 〜 1.0 |

9 要素 × 10 フレーム = 90 個の 1 次元テンソル `(90,)`

### パディング処理（重要）

過去フレームが足りない初期状態では**エッジパディング**を使用すること。
ゼロ埋めは「距離 0 = 中心にいる」と誤認するため禁止。

例: インデックス 2 のデータを取得する場合、
`[0], [0], [0], [0], [0], [0], [0], [0], [1], [2]`
のように最初のフレームを必要な分だけ複製して補完する。

### 出力データ仕様（2 ノード）

| # | 要素 | 範囲 |
|---|------|------|
| 1 | 目標の左モーター出力値 | -1.0 〜 1.0 |
| 2 | 目標の右モーター出力値 | -1.0 〜 1.0 |

### 学習スクリプト要件（train.py）

1. **Custom Dataset**: CSV から時系列順に読み込み、スライディングウィンドウ方式で
   `(90,)` に整形。エッジパディング処理を実装すること。
2. **モデル定義**: `nn.Module` 継承の MLP（90 → 64 → 32 → 2）、活性化関数は ReLU。
3. **学習ループ**: 損失関数 MSELoss、オプティマイザ Adam。
4. **ONNX エクスポート**: 学習後に `model.onnx` として保存。ダミー入力 `(1, 90)`。

---

## 実装順序

```
Step 1  走行ログ収集の仕組みを整備（フレーム保存を recorder.py に追加）
Step 2  軽量モデルを仮実装し Pi 実機でベンチマーク → 40ms 以内のサイズを確定
Step 3  確定サイズでアノテーション・フル学習（train_seg.py）
Step 4  NCNN INT8 エクスポート・Pi 実装
Step 5  camera_receiver.py の _build_line_mask() をモデル推論に差し替え
Step 6  動作確認・必要なら制御モデルを再学習（新検出出力に合わせて）
```

## 現時点の優先順位

```
今すぐ : 現在のルールベース検出の安定化（進行中）
並行   : 走行ログ収集・フレーム保存の仕組みを作る
次に   : 軽量モデルで Pi ベンチマーク → サイズ確定
その後 : 本格的なアノテーション・学習
```
